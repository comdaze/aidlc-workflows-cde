# 电力交易 Agentic PoC 架构模式（实战验证）

来源：2026-07 某省级现货市场储能交易 PoC 的 ADR（已脱敏）。两个模式在步骤
5-7 实现并经部署/测试验证，可作为同类 agentic 交易场景的起始架构。

## 模式一：预测能力封装在 MCP 缝后

**问题**：多个 agent 需要把"价格预测"作为工具调用；模型和推理通道未来大概率
更换。

**方案**：预测封装为独立 MCP 服务（如 FastMCP on Fargate 私有服务），agent
经服务发现别名调用。模型/端点替换成为双向门——只改 MCP 服务内部，agent 侧
零改动。

**实战教训**：
- ECS Service Connect 必须用其配置的**短别名**（如 `chronos-mcp:8000`）；
  自拼的 FQDN（`*.namespace.local`）不可解析——这是当次部署两次失败的根因。
- 保留 MCP 的 DNS rebinding Host 校验，用精确 allowlist 而不是禁用校验。
- PoC 内部明文 HTTP + 无服务间鉴权在私有子网可接受；生产化必须加 TLS 与
  鉴权——写进扩展建议，不静默留债。

## 模式二：确定性风控拥有决策权，LLM 仅生成措辞

**问题**：交易涉及安全边界（SOC、次数限制），LLM 输出不可作为安全决策依据。

**方案**：固定编排顺序 **预测 → 策略优化 → 风控 → 解释**。风控是确定性规则
引擎，在 LLM 之前执行、可返回一等公民的 blocked 结果；LLM 只把已定型的决策
翻译成面向交易员的自然语言说明，失败时落到确定性兜底模板，且解释文本始终
包含"不构成交易指令"声明。

**收益**（实测）：
- 安全行为可单测、可复现——风控逻辑是纯函数
- 演示不依赖外部 LLM 可用性（兜底模板保证 demo 永远能跑）
- 脱敏日志只存派生摘要 + 哈希，审计友好

**前提**：更换 LLM 供应商前必须先有评测集（eval set）——没有 eval 的 LLM
缝是"打得开但不敢走过去的门"。PoC 交接时 eval 集属于交付物。

## 适用性说明

两个模式合起来回答的是 agentic 交易系统的通用问题："哪里允许不确定性"——
预测可以换（缝后）、解释可以软（有兜底）、**决策必须硬**（确定性且先行）。
同构场景（能源调度、量化风控、供应链决策）可直接套用。
